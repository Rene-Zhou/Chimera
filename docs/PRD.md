---

## 1. 背景与机会

macOS 上缺少一款**现代设计、原生性能、专注 CHM** 的阅读器：

- **iChm**：最经典的开源 CHM 阅读器，但 UI 停留在十年前，长期无实质更新，不支持深色模式与现代检索体验；
- **App Store 付费应用**（ChmPlus、CHM Reader Pro 等）：质量参差，多为"转 PDF"思路，搜索弱、审美老旧；
- **通用阅读器**（OmniReader 等）：CHM 只是附属格式，目录树/索引支持不完整，大文件性能差。

## 2. 产品定位

> 为 macOS 打造的现代原生 CHM 阅读器——打开即读，搜索即达。

**核心使用场景（来自首要用户）**：阅读 TTRPG 规则书（如 5R 不全书）。典型行为是在跑团/备团时**快速查阅规则**：通过目录树浏览章节、全文搜索定位条目、多标签页同时对照多处规则。

## 3. 设计原则

1. **原生优先**：纯 Swift 实现，严格遵循 macOS Human Interface Guidelines；
2. **专注**：只做 CHM，不做通用电子书阅读器；
3. **隐私优先**：完全离线运行，无任何统计与上报；
4. **键盘友好**：高频操作均有快捷键，对标 Safari/预览的操作习惯。

## 4. 功能需求

### 4.1 P0 — v1.0 必须交付

| # | 功能 | 需求描述 | 验收标准 |
|---|---|---|---|
| F1 | 文件打开与渲染 | 支持双击关联 .chm、拖放到 Dock/窗口、File ▸ Open；使用 WKWebView 渲染 CHM 内嵌 HTML/CSS/图片；正确处理页面内链接与锚点跳转 | 基准文件打开后首页正常显示；点击页内链接正确跳转；无外部网络请求 |
| F2 | 编码兼容 | 依据 CHM 头 LCID + HTML charset 声明 + 内容嗅探确定编码，覆盖 GBK(CP936)、UTF-8、Big5、Windows-1252 等 | 基准文件（GBK）的目录、正文、搜索结果全部无乱码 |
| F3 | 目录树（TOC） | 解析 .hhc，以树形侧栏展示；点击节点定位内容；记住展开/收起状态 | 基准文件目录树层级完整、无乱码、可逐层展开导航 |
| F4 | 索引（Index） | 解析 .hhk，独立"索引"页签；支持输入即时过滤 | 输入关键词可过滤出对应索引项并跳转 |
| F5 | 全文搜索 | 全书关键词搜索；结果列表展示标题 + 上下文摘要；点击跳转并在页面内高亮命中词 | 在基准文件中搜索"法术"等高频词，结果完整、排序合理、跳转后高亮正确 |
| F6 | 页内查找 | Cmd+F 在当前页面内查找，支持上一个/下一个 | 与 Safari 页内查找体验一致 |
| F7 | 多标签页 | 现代标签页（Safari 风格）；Cmd+T 新建、Cmd+W 关闭；每标签独立的导航历史；支持同一本书在多个标签中打开 | 可同时打开基准文件的两个不同章节并各自前进/后退 |
| F8 | 历史导航 | 每个标签内前进/后退（Cmd+[ / Cmd+] 及工具栏按钮） | 跳转多次后可逐步回退到起点 |
| F9 | 书签 | 对当前页添加/删除书签；书签按文档持久化存储，可在侧栏/菜单中管理 | 重启应用后书签仍在，点击可跳转 |
| F10 | 显示自定义 | 自定义正文字体与字号；Cmd+= / Cmd+- 缩放；深浅色外观跟随系统 | 设置持久化，重启后保持 |
| F11 | 状态记忆 | 记住每本书的最后阅读位置；记住窗口尺寸与侧栏状态；提供"最近打开"列表 | 关闭并重新打开基准文件后，自动回到上次阅读位置 |
| F12 | 系统集成 | 注册 .chm 文件类型关联；Finder"打开方式"中可见 | 双击 .chm 文件默认用本应用打开 |

### 4.2 P1 — v1.x backlog（v1.0 明确不做）

导出 PDF/EPUB · 高亮标注与笔记 · 书库管理 · 跨文件全局搜索 · Spotlight/QuickLook 插件 · 打印 · AI 问答

### 4.3 Non-goals（长期不做，除非另行决策）

阅读模式重排（首要用户明确不需要）· EPUB/MOBI 等其他格式 · Windows/Linux 版本 · 账号体系与云同步

## 5. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 基准文件（7.8MB）冷启动到可阅读 < 1.5s；全文搜索首次建立索引可后台进行，搜索响应 < 500ms；目录树渲染流畅 |
| 稳定性 | 畸形/损坏的 CHM 不得导致崩溃，给出友好错误提示 |
| 隐私 | 完全离线；无网络请求、无统计上报 |
| 本地化 | 简体中文 + 英文，默认跟随系统语言 |
| 兼容性 | macOS 14 Sonoma 及以上（已确认）；Apple Silicon + Intel 通用二进制 |

## 6. 技术方案概要（指导方向，非实现细节）

- **语言/UI**：纯 Swift；SwiftUI 为主，必要时回落 AppKit（如目录树用 NSOutlineView）；
- **渲染**：WKWebView + 自定义 WKURLSchemeHandler，直接从 CHM 容器惰性读取资源，不做全量解压到磁盘；
- **解析层**：首期通过 SPM 桥接成熟 C 库 chmlib；解析层做接口抽象，保留未来替换为纯 Swift 实现的空间；
- **全文搜索**：打开文档时在后台建立自有索引并缓存（基准文件内嵌的 $FIftiMain 可作为二期优化项解析复用）；
- **最低系统**：建议 macOS 14.0；
- **依赖管理**：Swift Package Manager；无第三方统计/上报类依赖。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 中文 CHM 编码混乱（charset 缺失/声明错误） | LCID + charset 声明 + 内容嗅探三级回退；基准文件作为回归用例 |
| chmlib 年久失修（C 库安全隐患） | 解析层接口隔离；WebView 侧禁止外部加载，将恶意内容影响限制在沙盒内 |
| CHM 内嵌 JavaScript/恶意内容 | WKWebView 禁用外部网络加载，仅允许应用内 scheme |
| Homebrew 分发遇 Gatekeeper 拦截（无开发者账号公证） | v1.0 提供 `xattr` 说明文档；视发布反馈再决定是否做 Apple 公证 |
| 大型 CHM 性能 | 资源惰性加载；索引后台构建 + 磁盘缓存 |

## 9. 命名与图标（已定案）

- **正式应用名：Chimera** —— 双关：拼写以 "CHiM" 开头暗合 CHM；Chimera 也是 D&D 经典怪物，呼应 TTRPG 核心场景。
- **图标：已定稿**（由外部 AI 设计，首要用户选定），源文件 `assets/icon/chimera.svg`，预览 `assets/icon/chimera-preview.png`。
  - 设计：三头奇美拉（山羊/狮/龙，经典 D&D 构图）从翻开的书页中跃出；炭黑 × 暖米色双色木刻风，圆角矩形底。
  - M5 发布前的工业化处理：按 Apple 图标网格补安全边距（当前接近满版，Dock 中会略显大）；导出全套 iconset 尺寸；验证 16/32px 小尺寸下三头细节的辨识度。
- 仓库重命名与 bundle id 在 M1 工程初始化时确定（建议 bundle id 形如 `io.github.<用户名>.chimera`）。
